# IMU 行为识别算法方案

> 面向产品经理，阅读无需算法背景。

---

## 一、背景说明

智能项圈内置 6 轴 IMU 传感器（加速度计 + 陀螺仪），以 50Hz 频率采集狗狗颈部的运动数据。行为识别的目标是：**根据这段运动数据，判断狗狗当前在做什么**。

**第一阶段核心任务：抓挠识别**（用于 C-PVAS 评分）  
**后续扩充：走、跑、跳、玩耍、睡眠等完整行为分类**

---

## 二、三类算法方案对比

| 维度 | 传统规则 | 机器学习 | 深度学习 |
|---|---|---|---|
| **准确率（抓挠识别）** | 60%～75% | 85%～90% | 90%～94% |
| **推理速度** | 0.01s | 0.1s | 0.1s |
| **资源占用** | CPU | CPU + 内存较大 | GPU |
| **最低数据量** | 无需标注数据 | 500～3000 条标注 | 10000 条以上 |
| **开发周期** | 1 周 | 2 周 | 4 周 |
| **部署复杂度** | 低 | 低 | 较高（GPU 调度） |
| **适合阶段** | MVP / 快速验证 | 数据积累期 / 量产 | 数据充分后 / 高精度需求 |

---

## 三、方案一：传统规则

### 原理

不依赖标注数据，直接分析 IMU 信号的物理特征，用人工定义的规则判断行为。

### 抓挠动作的 IMU 信号特征

狗狗抓挠时，颈部会随后腿动作产生特定的节律性抖动，在 IMU 上表现为以下特征：

| 信号维度 | 抓挠时的特征 | 正常安静时对比 |
|---|---|---|
| 加速度幅值 | 0.3～1.5g 的中等幅值波动 | <0.1g 近乎静止 |
| 主频率 | 2～8 Hz（每秒抖动 2～8 次） | 无规律频率 |
| 节律性 | 重复性强，波形周期稳定 | 无明显周期 |
| 持续时长 | 单次抓挠 3～30 秒 | — |
| 轴向 | Y 轴（侧方）为主，Z 轴（垂直）次之 | — |
| 陀螺仪 | 颈部同步旋转摆动，角速度 20～80°/s | 接近 0 |

**规则判断逻辑（简化）：**

```
当前时间窗口（2秒）满足以下全部条件 → 判定为"抓挠"：
  ① 加速度幅值 > 0.3g
  ② 主频率在 2～8 Hz 范围内
  ③ 节律性评分（自相关系数）> 0.6
  ④ 持续时间 ≥ 3 秒
```

### 优势与局限

**优势：**
- 零数据依赖，设备出货即可使用
- 逻辑透明，产品可解释
- 极低资源消耗，可在项圈端本地运行初筛

**局限：**
- 对姿势变化适应差（同样的抓挠，小型犬与大型犬信号幅值差异大）
- 蹭墙、甩头等动作频率相近，容易误判为抓挠
- 阈值需人工调参，泛化能力弱
- 无法扩展到多行为分类

---

## 四、方案二：机器学习

### 优选方案：LightGBM

从 IMU 原始信号中提取人工特征，用 LightGBM 分类器学习特征与行为之间的映射关系。

相比同类的 XGBoost 和 CatBoost，**LightGBM 在服务端部署上更成熟**：内存占用更小、推理更快，Python 生态中有完善的 serving 支持，适合量产阶段上线。

### 特征工程（输入）

以 2 秒滑动窗口（100 帧）为单位，提取以下特征：

| 特征类别 | 具体特征 | 数量 |
|---|---|---|
| 统计特征 | 各轴均值、标准差、峰峰值、最大/最小值 | 6轴 × 5 = 30 |
| 频域特征 | 各轴主频、频谱能量、功率谱密度 | 6轴 × 3 = 18 |
| 节律性 | 自相关系数（lag=10/20/50ms） | 6 |
| 合向量 | 加速度合力向量幅值均值/方差 | 2 |
| 跨轴关系 | X-Y / Y-Z 相关系数 | 2 |
| **共计** | | **~58 维** |

### 输出标签

| 阶段 | 输出类别 |
|---|---|
| 第一阶段 | SCRATCH / 非SCRATCH（二分类） |
| 第二阶段 | SCRATCH / MOVE_WALK / MOVE_TROT / MOVE_RUN / MOVE_JUMP / SLEEP / UNKNOWN（多分类） |

### 数据需求

| 阶段 | 每类所需标注量 | 总计 |
|---|---|---|
| 第一阶段（二分类） | SCRATCH ≥ 2h，非SCRATCH ≥ 4h | 约 800～2000 条片段 |
| 第二阶段（多分类） | 每子类 ≥ 2h | 约 3000～8000 条片段 |

### 优势与局限

**优势：**
- 准确率显著高于规则（85～90%），满足产品需求
- 训练和部署门槛低，无需 GPU，云服务器即可
- 特征可解释，便于排查误判原因
- 新增行为类别只需追加数据，不用重新设计整体架构

**局限：**
- 特征工程需要领域知识，手工设计耗时
- 对极端体型（超小型犬/超大型犬）需分别调参
- 准确率天花板低于深度学习

---

## 五、方案三：深度学习

深度学习直接从原始 IMU 时序数据中自动学习特征，无需人工设计特征工程，但需要大量标注数据。

### 推荐路线

根据数据量和精度要求，分三个子方案：

---

### 5.1 1D-CNN 或 1D-CNN + GRU 混合

**适用场景：数据少（5000～20000 条）、快速上线**

| 组件 | 作用 |
|---|---|
| 1D-CNN | 提取局部时序模式（如单次挠动的波形） |
| GRU（可选） | 捕捉时序上下文（前后动作的关联） |

- 模型大小：<1MB，可轻量部署
- 训练时长：1小时内（单卡 GPU）
- 准确率：~88%（二分类）

**结构示意：**
```
原始 IMU 信号（6轴 × 100帧）
  → Conv1D × 3层（提取局部特征）
  → GRU × 1层（捕捉时序依赖）
  → 全连接层
  → 输出：行为类别概率
```

---

### 5.2 CNN + Transformer 混合（Conformer / PatchTST）

**适用场景：数据中等（20000～100000 条）、精度要求高**

| 组件 | 作用 |
|---|---|
| CNN | 提取局部特征（短时波形） |
| Transformer | 捕捉全局上下文（长时行为规律） |

**两种主流架构：**

- **Conformer**：语音识别领域迁移，擅长处理节律性信号（与抓挠特征契合）
- **PatchTST**：将时序切成 Patch 块后用 Transformer 处理，在传感器数据上表现优秀

- 准确率：~92%（多分类）
- 训练时长：4～8 小时（单卡 GPU）

---

### 5.3 PatchTST + 预训练微调

**适用场景：数据充足（>100000 条）、追求精度上限**

在大规模未标注 IMU 数据上先做**自监督预训练**（让模型学习 IMU 信号的通用规律），再用少量标注数据微调。

- 准确率：~94%
- 优势：预训练权重可复用到新品种、新物种（迁移学习）
- 局限：对基础设施要求高，训练成本高

---

### 深度学习优势与局限

**优势：**
- 准确率最高（90～94%）
- 自动特征提取，不依赖领域专家手工设计
- 预训练模型可迁移，后续加猫咪支持成本低

**局限：**
- 需要大量标注数据（万级别），冷启动阶段不适用
- 需要 GPU 训练和推理，云成本更高
- 模型黑盒，误判排查难度更大

---

## 六、总结与落地路线

### 推荐路线：机器学习先行，深度学习接力

```
现在（0～6个月）
  → 传统规则 + LightGBM 并行上线
  → 传统规则作为兜底，LightGBM 积累置信度
  → 目标：抓挠识别准确率达到 85%+

数据积累期（6～18个月）
  → LightGBM 正式替代规则方案
  → 开始收集细分行为标注，为多分类做准备
  → 标注量达到 5000+ 后，试验 1D-CNN + GRU

数据充分后（18个月+）
  → 引入 PatchTST 或 Conformer
  → 实现走/跑/跳/玩/睡眠全行为分类
  → 考虑预训练方案，为猫咪支持做迁移准备
```

### 各阶段精度预期

| 时间节点 | 方案 | 抓挠识别准确率 | 多分类支持 |
|---|---|---|---|
| 第0～3月 | 传统规则 | 65～75% | 否 |
| 第3～6月 | LightGBM（二分类） | 85～90% | 否 |
| 第6～12月 | LightGBM（多分类） | 82～88% | 是（5类） |
| 第12～24月 | 1D-CNN + GRU | 88～92% | 是（10类+） |
| 第24月+ | PatchTST | 90～94% | 是（全类） |

### 一句话总结

> **先用机器学习（LightGBM）快速达到可用水平，边积累数据边向深度学习演进，不盲目追求最高精度。**
